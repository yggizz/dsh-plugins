# 产物文件右键复制

在对话里右键任意文件，把它的**相对路径**、**文本内容**或**文件本体**复制到系统剪贴板。

## 三项复制

| 菜单项 | 作用 |
| --- | --- |
| 复制相对路径 | 以该会话工作目录为基准的路径，如 `artifact-copy/client.js` |
| 复制文件（可直接粘贴） | 文件本体，作为原生剪贴板文件列表（Windows `CF_HDROP`、macOS POSIX file、Linux `text/uri-list`），可粘进资源管理器、访达、微信、邮件 |
| 复制文本内容 | 文本文件的完整内容（上限 1 MiB） |

目录右键时第二项自动变成「复制文件夹」，粘贴行为与资源管理器一致。

## 为什么不提供「复制完整路径」

DSH 自带的 `open-in-app` 已经在同一份文件右键菜单里提供「复制文件路径」，重复一条同义项只会让菜单变长。本插件只补浏览器做不到的部分：**文件本体**、相对路径、文件内容，并排在自带项之后、带分隔线。

## 为什么需要 Host 半边

浏览器页面能往剪贴板写文本，但写不了「文件」这种原生格式——那是操作系统剪贴板的能力，Web API 没有暴露。所以右键动作的浏览器半边只捕获「会话 + 路径」，真正的复制由 Host 在文件所在的机器上执行：

- Electron 的 `clipboard.writeText` 优先（无子进程）；
- 退回系统命令：Windows `Set-Clipboard -Path/-Value`、macOS `pbcopy` 与 `osascript`、Linux `xclip`。

## 路径怎么解析

右键菜单捕获的是路径字符串。若它本身就是绝对路径则原样使用；否则以该会话的有效工作目录解析——交付卡片、行内文件引用、侧边栏文件树给的都是相对路径。

## 出现在哪里

任何已经绑定文件右键菜单的地方：交付文件卡片、回复正文中的文件引用、侧边栏文件树、改动对比的文件头。它们共用 `{ kind: 'file', value: { sessionId, path } }` 这个目标，插件不接管任何自有界面，也不改别人的菜单项。

## 安全

路由只接受本机回环请求，`Host` 头不是本机就直接 403，局域网来源无法驱动剪贴板。请求体上限 8 KiB，文件内容上限 1 MiB。

## 已知限制

- 复制文件本体依赖系统剪贴板提供程序；Linux 需要 `xclip`，缺失时该菜单项提示「系统剪贴板工具不可用」，路径与内容复制不受影响。
- 文件不存在时三项置灰并保持可见，行数不会在 2/3 项之间跳动；探测超时（约 600ms）时不禁用，改由点击后返回真实原因。
- 「复制文本内容」按扩展名白名单判定，非文本文件保持置灰。
